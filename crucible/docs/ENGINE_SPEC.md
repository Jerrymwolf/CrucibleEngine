# Crucible Engine core, v0 specification

The Values Crucible is a facilitated, multi-team crisis simulation. Six teams each run a parish of the island of Concordia during Hurricane Midas. The simulation exists to surface the gap between the values a team states before the storm and the values it enacts under pressure. The hurricane is the vehicle; the dilemmas are the lesson. Executives, not gamers, are the users.

This document specifies the headless simulation core. No UI, no network, no LLM calls live here. The core must be deterministic: same seed, same content, same inputs, byte-identical run log.

## Inputs

- `content/` JSON files (exported from the previous TypeScript constants; shapes are whatever the files contain, read them):
  - `concordia.json`: PARISHES (6, keyed by upper-case id, with position, population, keyAssets, resources, dependencies, vulnerabilities), PARISH_DEPENDENCIES, INFRASTRUCTURE (power, water, comms sources), RING_ROAD, CRATER_ROADS, SUPPLY_CHAIN.
  - `timeline.json`: HURRICANE_MIDAS windows (T-72h to T+24h) with weather, certainty, infrastructure failures, available decision types.
  - `infrastructure.json`: CASCADE_RULES (16), DEGRADATION_RATES, INFRASTRUCTURE_THRESHOLDS, INITIAL_INFRASTRUCTURE_STATUS.
  - `dilemmas.json`: ALL_DILEMMAS (45) with phase, parish, trigger, options, values tested, consequences, persona.
  - `personas.json`, `values.json` (VALUES_DECK of 40), `intensity.json` (10 levels, 7 levers, directive types), `decisionTypes.json`, `production.json`.
- A seed (u64).
- Optional scripted inputs: a JSON file of decisions keyed by dilemma id (`{"crisis-keystone-02": {"option_id": "b", "rationale": "..."}}`), an intensity curve (`[{"t": -4320, "intensity": 3}, ...]`), and directives. Anything not scripted is decided by the built-in controllers.

## Model

Time: discrete ticks of 15 simulation minutes from T-72h (t = -4320) to T+24h (t = 1440). Each tick runs, in this order:

1. **Window and weather.** Advance the hurricane timeline window from `timeline.json`. Interpolate wind, rain, surge between windows. Emit `window_transition` on change. The hurricane position moves along a track toward the island; the track may be perturbed by the seed so that the storm can weaken, strengthen, or shift, within the bounds the timeline allows.
2. **Degradation.** Apply weather degradation to each parish system using DEGRADATION_RATES, the parish's vulnerabilities, and the current intensity multiplier. Emit `degradation` events for changes of 5 points or more.
3. **Connectivity (Micropolis-derived).** Power, water, and communications are not independent per parish; they flow from sources over links. Sources and links come from `concordia.json` INFRASTRUCTURE, PARISH_DEPENDENCIES, RING_ROAD, CRATER_ROADS. Each tick, flood-fill from each live source across operational links; a parish not reached loses that system at a bounded rate per tick unless it has local backup (generators in `resources`), which buys a limited number of hours. Emit `connectivity` events on loss and restoration. Roads: a parish with no passable road path to any other parish is `isolated`; emit `isolation`.
4. **Cascades.** Evaluate CASCADE_RULES: when the trigger system in the trigger parish is at or below the threshold, schedule each effect with its delay. A rule fires at most once per run. Emit `cascade` when an effect lands.
5. **Scheduled effects.** Apply any delayed consequence or cascade effect whose time has come.
6. **Dilemmas.** For each parish, if no dilemma is open and the cadence allows (cadence rises with intensity), select an eligible dilemma: matches current phase, matches parish or is island-wide, trigger conditions met, not yet used. Selection order is deterministic from the seeded RNG. Emit `dilemma_presented` with a deadline.
7. **Decisions.** A parish with an open dilemma decides when its controller says so:
   - `script`: use the scripted option if present for that dilemma id.
   - `ai`: a drift model. Score each option as `alignment_with_stated_values * (1 - pressure) + expedience * pressure + noise`, where `pressure` is a function of intensity, the parish's own infrastructure loss, and time remaining before the deadline, and `noise` is small and seeded. Stated values come from `teams[]`. This reproduces the core finding of the design corpus: teams honor stated values at low pressure and drift under high pressure, and rationalize it. Emit `decision` with `values_signaled` and a templated rationale.
   - `human`: never decides in headless mode; the dilemma expires at its deadline with a default option marked as such.
8. **Consequences.** Apply the chosen option's immediate effects; schedule ripple and delayed effects; emit `consequence` events as they land.
9. **Snapshot.** Append the tick to the run log with infrastructure levels, morale, isolation, and the tick's events.

Intensity: the Crucible Master dial, 1..10. Default curve derives from the timeline (watch 3 to 4, crisis 5 to 9, recovery 5) unless scripted. Intensity multiplies degradation and dilemma cadence as described in `intensity.json` levers.

Values observation: for every decision, record the option's value signals on the -3..3 ABCD scale. If the content provides explicit per-option value signals, use them. If it only provides `valuesTested` for the dilemma and qualitative option text, derive signals with a documented, deterministic rule and say so in the code. At the end, compute `summary.values_gap` per parish: for each stated value, the mean enacted signal across that parish's decisions.

## Determinism

- All randomness comes from one ChaCha20 RNG seeded from `seed`. No wall clock, no HashMap iteration order in anything that affects output (use BTreeMap or sort).
- `crucible run --seed 42` twice produces byte-identical output. A test asserts this.
- `summary.state_hash` is a SHA-256 of the canonical final state. `crucible replay run.json` re-executes from the seed and the decisions recorded in the log and must reproduce the same hash.

## Property tests (proptest)

- Infrastructure levels stay within 0..100 for any seed.
- Each cascade rule fires at most once.
- Every `decision` has a matching prior `dilemma_presented`.
- `t` is strictly increasing by `step_minutes`.
- For any seed, replay reproduces `state_hash`.

## CLI

- `crucible run --seed <u64> [--content <dir>] [--decisions <file>] [--intensity <file>] [--teams <file>] --out <file>` prints a readable timeline table (time as T-72:00 style, window, intensity, notable events) and writes the run log.
- `crucible replay <run.json>` re-executes and prints OK with the hash, or a diff of the first divergence.
- `crucible validate [--content <dir>]` checks referential integrity: dilemma parish ids exist, cascade rule parish and system ids exist, timeline windows are monotonic, persona ids referenced by dilemmas exist. Exit non-zero on failure.
- `crucible summary <run.json>` prints per-parish outcomes and the values gap table.

## Code shape

- Cargo workspace at `crucible/` with crates `crucible-core` (library) and `crucible-cli` (binary).
- Modules in core: `content`, `state`, `rng`, `weather`, `connectivity`, `cascade`, `dilemma`, `controller`, `values`, `sim`, `log`, plus `morale` (amendment 3) and `validate`. No file over 400 lines. Unit tests beside the code, integration tests in `tests/`.
- Dependencies: serde, serde_json, rand, rand_chacha, sha2, thiserror, anyhow, clap, proptest. Nothing else without a reason stated in a comment.
- `cargo test` and `cargo clippy --all-targets -- -D warnings` must pass.
- Content is never embedded in Rust source. The core reads the JSON directory at runtime. Facilitators edit content, not code.

## What is out of scope for v0

Server, websockets, persistence beyond the run log, any UI, any LLM call, authentication, reports. Those come after the headless core replays a session identically.

## Amendments, 2026-10-18 overnight build

1. **Run length.** The run continues 24 hours past the start of the final timeline window (T+48h with the current content), so recovery-phase dilemmas are presented and decided. Ending at the window start left recovery one tick long. Constant `RECOVERY_PLAY_MINUTES` in `sim.rs`.
2. **Connectivity capacity (from the REA brief, e.1).** Power is served from the source in content priority order, then by population; the number of parishes carried is `ceil(source_power / 20)`. Parishes with backup generators hold power at or below 60 for 24 hours (priority parishes) or 12 hours (others) while disconnected. Constants live in `connectivity.rs` until content carries them.
3. **Morale integrator (e.3).** Per-parish pressure in -2000..2000 updated hourly from `(service_index - 1) * 60` plus 50 times each decision's summed value signals; morale tracks `50 + pressure / 40` with smoothing 0.25 per tick; isolated parishes do not recover. The gain was lowered from the reference's 150 after it saturated within a day of landfall.
4. **RNG draw counts (e.5).** Each tick logs `rng_draws`; a property test asserts the per-tick counts are identical across two runs of the same seed.
5. **Known limits.** No directive or narrative events yet; the timeline's authored infrastructure states are not used as forcing inputs; numeric consequences are derived from value signals because content carries only narrative sketches; calibration is first-cut.

## Amendment, 2026-10-20: live mode

Decided with Jerry for the nursing leaders session; see `../../CrucibleDocumentInventory/decision-2026-10-19-nursing-leaders-60min.md`.

- `RunConfig.live` (CLI `run --live`). Teams with controller `human` never decide headlessly. In live mode the run halts at the first tick where a human team has an open dilemma with no scripted decision, before that tick's decisions are taken, and returns the log so far with `pending` listing those dilemmas.
- To continue, add each pending decision to the scripted decisions with `t` set to the reported tick and run again from the seed. Because a run costs about 60 ms, re-running from the seed is the whole mechanism: no hidden session state, and the halted log is an exact prefix of the continued one (tested in `tests/live.rs`).
- A human team's entered decision is logged with controller `human`, not `script`.
- Runs without `live` are unchanged: the committed seed-42 run is reproduced byte for byte.

## Amendment, 2026-10-20: session profile and the browser build

- `RunConfig.ask` (CLI `run --ask <file>`, a JSON list of dilemma ids). When set, a human team is asked only those dilemmas; its other dilemmas are decided by the drift model exactly as for an `ai` team and logged with controller `ai`. This is how a 60-minute session asks each table four questions while the island keeps its full arc. Replay needs nothing new: it scripts every recorded decision. Tested in `tests/live.rs`.
- A table may decide an asked dilemma before it is presented (a scripted decision with no `t`); it lands on the tick the dilemma appears. The board uses this to put all six tables' questions on the screen at once.
- `crates/crucible-wasm` builds the core for `wasm32-unknown-unknown` with the content embedded at compile time (`Content::from_files`, same content hash as the directory). It exposes `crucible_run` over a plain C ABI, JSON in and run-log JSON out. `rand` and `rand_chacha` are built without default features so no OS entropy source is linked; seed-42 output is unchanged.
- Session profiles live in `content/sessions/*.json`. They are not part of the content hash; they choose what the board asks and are read only by `board/build.mjs`.

## Amendment, 2026-10-21: inputs, the allocation round, calls for aid, routes, residents and the doses tally

The engine half of the RTS flow (`../../CrucibleDocumentInventory/decision-2026-10-21-rts-experience-flow.md`, sections 4, 8 and 10) against the v3 canon. The choices are recorded in `../../CrucibleDocumentInventory/decision-2026-10-21-engine-allocations-aid.md` (status: proposed); the scoring tables are defaults to be tuned. Every number below lives in `content/`; the Rust carries the rules and two named defaults, `routes::DEGRADED_WIND_MPH` and `aid::DEFAULT_ANSWER_TICKS`, until content carries them.

1. **Content.** Thirteen files, hashed in `content::FILES` order: `aid.json`, `concordia.json`, `decisionTypes.json`, `dilemmas.json`, `infrastructure.json`, `intensity.json`, `personas.json`, `production.json`, `residents.json`, `resources.json`, `routes.json`, `timeline.json`, `values.json`. Dilemma options carry structured `effects` (resident `groups` and `cards`, `doses`, `stock`, `infrastructure`, `generatorHours`, `shelterPlaces`, `powerPriority`, `sends`, `routes` overrides, `flags`, `declareHidden`, `raisesCall`, `answersCall`, and `chance` with `p`, `then` and `else`; `atT` defers an effect and `untilT` schedules its follow-on; `unlessFlag` and `ifFlag` gate it) and a `defaultOptionId`. `timeline.json` adds the four `quarters`, the `eyeWindow` and a suggested `intensity` per window. `crucible validate` checks every reference these files make (`validate.rs`).
2. **Inputs** (`inputs.rs`). `RunConfig.inputs` is a list of `{t, seq, kind, ...}` records; `kind` is one of `lock_values`, `allocate`, `decide`, `mayday`, `answer_aid`, `declare_hidden`, `repair_send`, `credit_line`, `swap_dilemma`, and the other fields follow `Input`. Records are sorted by `(t, seq)` and applied at the first tick whose time is at or after `t`, after that tick's storm effects and hazards and before its decisions. An input that cannot apply (a closed call, an allocation after the lock, a card that is not open, a parish with nothing hidden) is logged as a `rejected` event and changes nothing. Scripted and recorded decisions take precedence over a `decide` for the same card; a `decide` for a card not yet presented lands when it appears. `lock_values` replaces the team's stated values (and keeps its statement) from that tick on, logged as `values_locked`. Inputs at or after a tick never touch earlier ticks, so the log of a run with the inputs so far is an exact prefix of the run with one more (`tests/board.rs`): the board re-runs from the seed on every action, as live mode already did.
3. **Horizon.** `RunConfig.until` stops the run after that tick. The log then carries `until` and `open_calls` and, for human cards still open, `pending`.
4. **Session profile in the core** (`inputs::Session`, read from `content/sessions/*.json` by `Session::from_profile`). This supersedes the 2026-10-20 note that profiles are read only by the board build; they stay outside the content hash. The core uses `ask` (per parish: dilemma ids, as before, or `{dilemmaId, presentT, deadlineTicks}`), `maydays` (`{callId, t, answerTicks}`), `allocation.lockT` and `intensity` (`[[t, level], ...]`). A scheduled card is presented at the first tick at or after `presentT` on which the parish has no open card; its deadline is that tick plus `deadlineTicks` ticks; a parish with a schedule receives no random dilemmas. When a human card's deadline passes undecided, the storm applies the card's `defaultOptionId` (its first option when none is named), logged as a `decision` with `expired: true`, `decided_by: "storm"` and the team's controller. Since 2026-10-21 (audit fix, item 15) it carries no values signal: its effects apply, its rating does not. `swap_dilemma` replaces a scheduled card not yet presented, or an open card, which keeps its deadline.
5. **Intensity.** Precedence: `RunConfig.intensity`, then the profile's curve, then each window's suggested `intensity`, then the old phase mapping. The eye window degrades at the crisis rate (`weather::degradation_key`).
6. **Tokens and the allocation round** (`resources.rs`). Sheets start from the `STOCKPILES` in `resources.json`; `HIDDEN` reserves sit off the sheet until `declare_hidden` (or an option's `declareHidden`) puts them on it. `allocate` entries (`to` a parish, or `keep`) are held until `allocation.lockT`; a run without a lock rejects them. At the lock, sends become convoys and each human table is scored by the `SIGNALS` tables: per send, `sendNeededBeforeYou`, `sendGreatestNeed`, `sendLastNeeded` and `fundToAsked` as they apply (`resources::score_send`); per kept token, `keepNeededByLandfall` or `keepUnneededWhileListed`, aggregated into one keep record; `keepEverything` for a table that wrote nothing. Signals are summed per value and clamped to -3..3. Each record enters the values gap with `kind: "allocation"`: `dilemma_id` `allocate:<TOKEN>` with `option_id` `send:<parish>`; `allocate:keep` with `keep` or `keep_everything`; `declare_hidden` with `declare`. A delivered token applies its `EFFECTS` entry (generator hours, fuel, shelter places, cold bays, repair crews that mend roads and power through the recovery windows, water). `repair_send` (`kind: "repair"`, `repair:<TOKEN>` / `send:<parish>`, scored by `repairSend` and `fundToAsked`) and `credit_line` (`kind: "credit"`, `credit:<parish>` / `credit`, scored by `creditLine`) are the recovery actions.
7. **Routes and convoys** (`routes.rs`). `routes.json` names every route with its mode, travel and degraded times, `cutT`, `reopenT` and `eyeOpen`; effects may override the cut and reopen times. A parish is isolated when no open road route touches it; the 2026-10-18 road physics is removed. A convoy follows the shortest open road path (Dijkstra over travel times, degraded times once the wind reaches `DEGRADED_WIND_MPH`), arrives at the first tick at or after its travel time, and is checked for arrival before a cut at the same tick. A cut under a convoy turns it back (`convoy_turned_back`); the token returns to the sender's sheet at the end of the quarter (`token_returned`).
8. **Calls for aid** (`aid.rs`). A call from `aid.json` is raised by the profile's `maydays`, by an option's `raisesCall`, or by a `mayday` input from the asker; its deadline is the earlier of the call's `windowClosesT` and `t + answerTicks × 15` (the profile's `answerTicks`, else the call's, else `DEFAULT_ANSWER_TICKS`). A human holder answers by `answer_aid` with `grant`, `refuse` or, where the call allows it, `part` with a `count`; an AI holder answers at half the window: `grant` when the route is open and the count still leaves it its own listed needs from this quarter on, `part` when the route is open and it holds more than its needs, else `refuse`. At the deadline an unanswered call takes the call's `silenceAnswer`, logged with `controller: "silence"` and scored. A granted token travels as a convoy over the call's route, or the shortest open road path when the call names none; when that route is already cut the answer is logged `delivered: false` and the token is lost for the quarter, as the canon says; the call's `delivered` effects apply on arrival. An option's `answersCall` closes the call unscored and without the call's effects (the card carries its own). Aid records enter the gap with `kind: "aid"`, the call id and the answer.
9. **Residents** (`residents.rs`). Groups are count buckets over `safe`, `sheltered`, `at_risk`, `rescued`, `injured` and `lost`; cards are single named people with one state. Options, call effects and the storm's own `hazards` in `residents.json` (gated by flags) move them and log `resident_state`. `people_safe` is the island's population less `at_risk`, `injured` and `lost`.
10. **Doses tally** (`tally.rs`, every number from `production.json`). Production while Keystone's power and water hold and concentrate remains; loading of the consignment less batch 47 while Haven's port stands; the ship sails at its hour, or later when an effect holds it, and carries whatever is aboard; the vault runs on its battery when Keystone is dark with no generator and spoils when it runs out; the next consignment sails or is missed. A dose effect moves doses between the vault, the ship, a held batch and the shipped total; what no pool takes is `doses_lost`.
11. **Counters** on every tick and in the summary: `doses_shipped`, `people_safe`, `vault_doses`, `aboard`, `at_risk`, `injured`, `lost`.
12. **Hash.** Every tick carries `state_hash`; the last equals `summary.state_hash`. `HashedState` covers the time, infrastructure, morale, isolation, fired rules, every decision record (dilemma, allocation, aid, repair, credit), stock, hidden reserves, cut routes, convoys, counters, groups, cards, flags, answered calls and the doses. `replay` feeds back the seed, the teams, the recorded decisions, the recorded intensity curve, the inputs, the session and `until`, and compares every tick's hash to name the first divergence.
13. **Run log 0.2.** See `RUN_LOG_SCHEMA.md`. **WASM:** the request gains `inputs`, `until` and `session` (an embedded profile id, a profile object, or a run log's `session` block); `crucible_content(name)` hands out an embedded content or session file and `crucible_version()` describes the build; `crucible_run` with only a seed behaves as before. **CLI:** `run --inputs <file> --until <t> --session <id|path>`; `validate` reports routes, calls and groups too.
14. **Tests.** `tests/board.rs`: ten scenarios covering a byte-identical session run and its replay, per-tick hashes, prefix stability, the allocation lock and its scoring, aid granted, refused and answered by silence, the storm's default at the deadline, an eye-window delivery that misses the eye and returns, recovery sends and credit lines, the counters, and swapping a scheduled card. `tests/properties.rs`: Board invariants for random seeds and input sets (counters within the population and consistent, stock never negative, every tick hashed and the last hash the summary's, every answer after its call, no convoy crossing a route cut beneath it, replay reproducing the hash). `tests/determinism.rs`: `runs/seed-42.run.json` is a golden file; it changed with this amendment (new content, new fields) and was regenerated deliberately.
15. **Code shape.** New modules `aid`, `effects`, `inputs`, `residents`, `resources`, `routes`, `tally`. The 400-line guideline still holds for the logic modules; `content.rs` (one struct per JSON shape), `sim.rs` (the tick), `log.rs` and `state.rs` (record definitions) exceed it. That is debt to split, not a new norm.

15. **Audit fix, 2026-10-21** (`CrucibleDocumentInventory/decision-2026-10-21-audit-fix-spec.md`, cut A). The engine rates the answer, never the weather. Storm moments (a card past its deadline, a call answered by silence, an allocation round with nothing entered) carry no values. A move the engine rejects is not rated. `values_gap` keeps one piece of evidence per moment per value (the strongest signal; ties to the negative), lists storm moments unrated under the values their card tests, and flags a value `tested` once two chosen moments touch it; `enacted_score` remains only for the legacy viewer. Cost-free moves rate at most +1 (`resources.json` SIGNALS). Resident hazards may take a `share` of whoever is still in `from`, so the storm takes a share of everyone a table left exposed; the counters add `lowest_people_safe` and `people_hours_at_risk`. The v3 deck keeps at most one +3 and one -3 per card, every +3 names its `cost`, coerced compliance names its `pressure`, and `validate` enforces it. The host turns the DM's heat and cool into shorter or longer windows for cards and maydays that open after them (`heatStepTicks` per quarter), recorded in the run log's `session`, so replay holds. Run log version 0.3.
