# Crucible Engine, project memory for Claude Code sessions

Read this first. It is the handoff between sessions.

- **What this is:** The Values Crucible, a facilitated multi-team crisis simulation for leadership development. Six teams each run a parish on the island of Concordia during Hurricane Midas. The product surfaces the gap between stated and enacted values under pressure. Users are executives, not gamers. Aesthetic (2026-10-21): plays like an RTS strategy game (PixiJS map over the Rust core, see `crucible/board-rts/`), still readable by executives at a glance.
- **Current direction (2026-10-21):** all Godot. One Godot project holds the rules, the room networking and the app (tablets, laptops, web); see `CrucibleDocumentInventory/decision-2026-10-21-all-godot.md`. Jerry played the board and judged it "not an actual RTS": units must be ordered on the map, dilemmas must come out of map situations in real time, and the values at stake are named at the moment of choice. The Rust code under `crucible/` (the 2026-10-18 restart) is the reference until Godot matches it; do not extend its card loop. The TypeScript in `apps/` and `packages/` stays abandoned.
- **Design corpus:** `CrucibleDocumentInventory/` holds the narrative and research design documents. Decision records in that folder are named `decision-YYYY-MM-DD-*.md`; read the newest `status: accepted` one before proposing architecture.
- **Canon v3 (2026-10-21):** the parish redesign is decided in `CrucibleDocumentInventory/decision-2026-10-21-parish-leadership-redesign.md`. Current lore: `concordia-parishes-v3.md` and `concordia-storm-quarters.md`. Draft content (residents, secret briefs, resource tokens, calls for aid, 24 dilemmas): the `crucible-*-v3.md` files. Session format: `values-crucible-session-90.md` (15 brief, 60 play in four 15-minute quarters, 15 debrief). Older lore docs carry `status: superseded` in their frontmatter. `crucible/content/*.json` has not yet been converted to v3.
- **Content is data:** `crucible/content/*.json` holds parishes, timeline, cascade rules, dilemmas, personas, values, intensity levers. Edit content there, never embed it in Rust.
- **Contracts:** `crucible/docs/ENGINE_SPEC.md` (model), `crucible/docs/RUN_LOG_SCHEMA.md` (output). Changing either is a decision; record it.
- **Determinism is non-negotiable:** one seeded RNG, ordered maps, no wall clock in the core. `crucible run --seed N` twice must be byte-identical; `crucible replay` must reproduce the state hash.
- **Replay viewer:** `crucible/viewer/template.html` plus `build.mjs`; the built page is published as a claude.ai Artifact (link in `crucible/README.md`). Republish the same file to keep the URL.
- **Build logs:** `CrucibleDocumentInventory/YYYY-MM-DD-*-build-log.md` record what was done, measured, and left undone in each long session.
- **Memory strategy:** Jerry keeps decisions in Obsidian. Write new decision records with YAML frontmatter and wikilinks so they drop into the vault unchanged.
