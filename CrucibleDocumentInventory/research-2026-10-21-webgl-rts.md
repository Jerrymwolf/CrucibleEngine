# Research: how browser and WebGL real-time strategy experiences are built

Written for Jerry on 2026-10-21 to inform the RTS-feel direction in [[decision-2026-10-21-rts-experience-flow]] and the six-parish, allocation-and-aid design in [[decision-2026-10-21-parish-leadership-redesign]]. It is a reference, not a decision. Every claim carries a link; where a source did not say something and I am inferring, the text says "inference".

**The requirements this was researched against.** The Values Crucible must feel like an RTS video game; it is a dynamic, interconnected multiplayer experience between six tables, each the leadership of one Concordia parish, sharing or hoarding resources during Hurricane Midas; it renders with WebGL (PixiJS) in the browser on top of a deterministic Rust core compiled to WASM; it must survive venue wifi failure; and its users are executives, not gamers.

**The one-paragraph answer.** Build it the way the good RTS engines are built and the way the good facilitated simulations are run, and notice that those two traditions agree. Keep a hard wall between a deterministic simulation and a presentation layer (Spring's synced/unsynced split, 0 A.D.'s serialization rules, Age of Empires' synchronized RNG). Send only commands over the wire, never state; keep one ordered command log; hash the state every tick so divergence is caught (the "1500 archers" lineage). Run the host on the facilitator's laptop on a travel router you own, because venue wifi isolates clients from each other and plain `http://192.168.x.x` is not a secure context, so service workers and WebGPU are off the table anyway; WebGL and WebSockets are not. Join by a short code on a shared screen with no accounts (Kahoot, Jackbox). Give the facilitator the controls a crisis-exercise controller has (publish or pause injects, add or move participants, observe) and the pacing a classroom simulation has (the facilitator advances the day). For the feel, copy strategic zoom's icon layer, Mini Metro's self-explaining board, Frostpunk's forecast bar, Twilight Struggle's opponent-triggered cards and hidden scoring, Pandemic Legacy's "panic, then give them a problem and a solution", and Fishbanks' two prizes.

## 1. Exemplars and what makes them feel good

### 1.1 Browser and open-source RTS

**Chrono Divide (Red Alert 2 in the browser).** A fan project that recreates the full RA2 engine with web technologies, "with no additional plugins or applications installed", playable "on any device and operating system, directly from your web browser" including tablets. Its multiplayer is explicitly client-server, which it presents as "the best connectivity" and as eliminating port forwarding and firewall exceptions; it offers replays of your own games and few-click mod installation; its stated minimums are a 64-bit OS, 4 GB RAM (8 recommended), Intel HD Graphics or better and 1024x768, with a note to avoid Firefox for performance ([chronodivide.com](https://chronodivide.com/)). It was in public beta (v0.37) in November 2025 ([Gigazine](https://gigazine.net/gsc_news/en/20251121-command-conquer-red-alert-2-chrono-divide)). Neither its site nor the press coverage names the renderer, so I cannot confirm the Three.js rumour. Lessons: a complete RTS runs in a browser on integrated graphics; replays are a first-class feature; the project chose client-server over peer-to-peer for connectivity reasons, which matches our venue constraint.

**OpenFront.io (a Territorial.io-like).** An open-source browser RTS about territorial control and alliance building. The repository separates `/src/client`, `/src/server` and a deterministic simulation in `/src/core`; replays depend on that determinism and a production game can be replayed only on the same commit, identified by its `gitCommit` ([OpenFrontIO README](https://raw.githubusercontent.com/openfrontio/OpenFrontIO/main/README.md)). Lesson: version-pin the run log to code and content, which our `summary.state_hash` and content hashing already do; keep doing it when the browser client ships.

**Territorial.io.** Its developer describes it as "a simple strategy game" won by conquering 50% of the territory ([html5gamedevs thread](https://html5gamedevs.com/tags/territorial.io)). Lesson: one rule, one number on screen. Our two counters (doses shipped, people safe) are the equivalent.

**Screeps.** The server's tick has two stages, player scripts then per-room command processing, each a Redis task queue worked by separate machines; all database changes are written in bulk after both stages, then the next tick begins ([Screeps architecture](https://docs.screeps.com/architecture.html)). The planned standalone server was to ship as an Electron app with an embedded in-memory database so a player could run a server at their own IP with nothing else installed ([Screeps blog](https://blog.screeps.com/2016/09/Standalone-server-development-update/)). Lessons: tick, collect commands, apply, write once; a self-contained "server in a laptop" package is an established pattern.

**Command & Conquer source.** EA released Tiberian Dawn, Red Alert, Renegade and Generals/Zero Hour under GPL v3 on 28 February 2025 at github.com/electronicarts ([GameFromScratch](https://gamefromscratch.com/ea-release-command-conquer-series-source-code/)). Reference reading for how a classic RTS structures its command loop and UI, not code to reuse (GPL).

**0 A.D. (Pyrogenesis).** Engine under GPL-2.0-or-later, C++ and JavaScript, multiplayer described as peer-to-peer with no central server ([Wikipedia](https://en.wikipedia.org/wiki/0_A.D._(video_game))). Its serialization design states the determinism contract plainly: "basic deterministic state" must be identical across all players, derived state must be exactly recomputable from it, non-deterministic state may differ; the state is hashed to detect out-of-sync; a joining player needs a compact, secure machine-readable snapshot; the API uses only fixed-size types so the simulation stays deterministic across 32- and 64-bit builds and compilers ([Pyrogenesis serialization](https://docs.wildfiregames.com/pyrogenesis/serialization.html)). The engine's default number type is `CFixed_15_16`, "a fixed-point number class with 1-bit sign, 15-bit integral part, 16-bit fractional part" ([Fixed.h](https://svn.wildfiregames.com/docs/Fixed_8h.html)). Lesson: write down which state is canonical, which is derived and which is cosmetic, and hash only the first two.

**Beyond All Reason / Recoil (Spring).** Recoil is "a fork of the classic SpringRTS game engine" ([GamingOnLinux](https://www.gamingonlinux.com/2026/07/impressive-grand-scale-rts-game-beyond-all-reason-gets-a-major-engine-upgrade-with-arm64-support/)). Spring's development guidelines are the clearest short statement of lockstep discipline: only input is sent over the network; synced code "can write anything but should read only synced data", unsynced code "can read anything but must not write synced data"; initialize every variable "even if the value seems irrelevant, because it may unsync the simulation"; guard array bounds; take random numbers only from the synced generator and never from unsynced code; never key an ordered container by pointer ([Spring development guidelines](https://springrts.com/wiki/Development_guidelines)). Game logic lives in synced Lua and drawing in unsynced Lua, with `SendToUnsynced` as the one-way bridge ([Lua sync to unsync](https://springrts.com/wiki/Lua_sync_to_unsync)). Lesson: this is exactly the Rust-core / PixiJS-shell boundary. Name it that way in the code.

**Age of Empires Online.** Launched August 2011 as a free-to-play MMORTS, "okay at launch" but with a business model the producer called "a disaster" ([GDC Vault abstract](https://gdcvault.com/play/1018176/F2P-the-Wrong-Way-Age)). The $75 spending cap kept the biggest supporters out, the content pipeline could not keep up with demand, and the poor launch reputation stuck: "You only get word-of-mouth once" ([Quarter to Three](https://www.quartertothree.com/fp/2013/08/19/this-is-how-you-kill-age-of-empires/)). Lesson for us: a branded experience in front of executives gets no soft launch, and the content pipeline (the dilemma deck and resident cards) is the product.

### 1.2 RTS readability: zoom, units, interface

**Strategic zoom (Supreme Commander).** Built because top-tier units were about a hundred times the size of a basic bot and no single zoom level could show a game; Chris Taylor's framing was that "strategy happens before the battle, and tactics happen during the battle", and the camera runs from a truck-sized robot to a 6,000 km² theatre ([PC Gamer](https://www.pcgamer.com/uk/the-making-of-supreme-commander)). Zoomed out, units become abstract markers (radar blips in SupCom 2, bars in Sins of a Solar Empire), which lets a player watch a whole battlefield without juggling a minimap; Relic noted the feature depends on level-of-detail swapping and raises minimum spec without it ([Matchstick Eyes](https://www.matchstickeyes.com/tag/rts-zoom/)). Lesson: a projector shows one zoom level. Design the island at that level with an icon layer, and let tables zoom on their own screens.

**StarCraft II (Dustin Browder).** Early builds had clarity problems: when units stacked "you really had no idea of what was happening on the battlefield"; too many units made it "difficult to know what to build at any given moment", so the team cut each race from 15-18 units to 14; the campaign exists to make players "comfortable with the UI"; and the pacing goal was "Every move you make for the next fifteen minutes could determine your victory or defeat" ([Game Informer](https://gameinformer.com/b/features/archive/2010/04/08/an-extensive-interview-with-starcraft-ii-design-director)). Lesson: fewer, visually distinct resource and unit types; a 15-minute quarter is the right unit of dread.

**Dave Pottinger (Ensemble).** Health bars exist because "players need to read critical information at a glance"; Age of Empires III's UI "grew too large" because the team tried to please everyone; Halo Wars' Select All button, added under time pressure, flattened unit differentiation; a UI should be functional, consistent and responsive; "slower play is valid"; watch skilled players test ([Wayward Strategy interview](https://waywardstrategy.com/2015/05/04/lets-talk-rts-user-interface-part-1-interview-with-dave-pottinger/)).

**Strategy UI dos and don'ts.** Centralize the information pane; notify players of key events (idle workers, attacks, completions) with visible cues; back every hotkey with a visible control and show the hotkey on the button; reveal mechanics in tiers (Age of Empires III); do not spread commands over three screen regions (Planetary Annihilation); do not let important events happen unnoticed; and "minimalism is not a virtue in RTS design" when it costs usability ([Game Developer](https://www.gamedeveloper.com/design/ui-strategy-game-design-dos-and-don-ts)).

**Fog of war.** Withholding information makes knowledge "a resource to take or protect" and acting on partial information a skill; the author also argues full-information designs are valid and that fog should be costly to gain and easy to lose rather than mandatory ([Wayward Strategy](https://waywardstrategy.com/2015/01/30/battlefield-uncertainty-and-fog-of-war/)). For us, fog is social, not spatial: tables see their own parish fully and other parishes only through reports and asks, and a cut road or comms link degrades what they know. That is the hurricane's fog.

**Onboarding newcomers (Age of Empires IV).** The studio lead described "analytic-based tutorialising": the game watches how you play and, if you ignore a mechanic that would make the game easier, points it out; Art of War missions teach specific situations ([KitGuru](https://www.kitguru.net/gaming/matthew-wilson/age-of-empires-iv-will-use-analytic-based-tutorials-and-art-of-war-missions-to-teach-players/)). Lesson: the facilitator board can surface the same nudges for tables (for example, "Gateway has not answered a mayday yet").

### 1.3 Crisis and tabletop games that make pressure legible

**Frostpunk.** Marta Fijak's core lesson was "Empathising with 500 people is hard": by the endgame with around 700 citizens players "stop seeing individuals and see only numbers"; a prototype that bonded players to individuals (pausing when one died) did not land, and a prototype that bolted plot threads onto the city-builder "felt like two separate games"; the emotional weight came from long-term consequences and ending slides that judged the player's choices ([PCGamesInsider](https://www.pcgamesinsider.biz/news/67933/11bits-marta-fijak-empathising-with-500-people-is-hard-in-frostpunk/)). A critical-play analysis notes the forecast bar (a freezing thermometer icon warning of the drop, a warm icon for relief) drives the pacing, that the "cycle of looming danger and relief creates strong pacing", that generator overdrive percentages make strain visible, and that dilemmas lose force when the ethical choice is also the obviously efficient one ([Indienova critical play](https://lab.indienova.com/indie-game-review/critical-play-report-frostpunk/)). Lessons: three or four named residents per table is the right scale; the hurricane track is our forecast bar; never make a dilemma's values choice also its efficiency choice; judge choices in the debrief, not mid-game.

**Mini Metro.** The postmortem says the game "communicates the idea of itself very well": a screenshot explains it, because it borrows a transit map, and constraints (no hand-built levels, nothing art-heavy) pushed the team to procedural abstraction with Helvetica and MTA-style graphics ([Game Developer postmortem](https://gamedeveloper.com/audio/postmortem-dinosaur-polo-club-s-i-mini-metro-i-)). Pressure is legible as crowding stations; sessions run 10-20 minutes; procedural chimes mark events ([Game Developer analysis](https://www.gamedeveloper.com/design/let-s-talk-about-mini-metro)). The studio's stated method is "very approachable mechanics" whose depth appears with playtime ([GDC Vault abstract](https://www.gdcvault.com/play/1029197/Independent-Games-Summit-Expanding-the)). Lesson: the Concordia board should read like a civic map, not a game; sound should mark events.

**Two Point Hospital.** The goal was "accessible but deep", with simple entry points and complexity in layers; the UI target was "easily readable, chunky and accessible"; and the team "underestimated just how much work the UI was going to be", which became the most collaborative task on the project ([MCV](https://www.mcvuk.com/when-we-made-two-point-hospital/)). Budget the UI accordingly.

**Plague Inc.** The CDC invited its creator because the game raises awareness of epidemiology and transmission; its infection cycle is built on the basic reproduction rate; the designer researched the models himself and wanted "deeper strategy, a stronger narrative, and more realism" than earlier flash games ([CDC blog](https://blogs.cdc.gov/publichealthmatters/?p=5601)). He says it "was designed to show serious issues sensitively without sensationalising it" and is meant to be left and returned to ([PocketGamer.biz](https://www.pocketgamer.biz/interview/73676/live-and-kicking-plague-inc-ndemic-creations/)). Lesson: a serious subject on a readable world map with a few counters is a proven form, and tone discipline matters.

**Pandemic Legacy.** Rob Daviau's design brief for a scenario: "Now the player should be completely panicked because X is happening", then give players a problem and a solution; the team avoided "game over that was your last month" and gave failed months a "make-up test"; players should "see the framework so you knew where you were going"; information is dripped "in a controlled way"; permanence gives a "visceral thrill" because "there's no turning back" ([Z-Man Games Q&A](https://www.zmangames.com/en/news/2017/10/25/a-qa-with-the-designers-of-pandemic-legacy/)). Difficulty tracks the group: losing a month adds funded-event cards, winning removes them ([PC Gamer](https://www.pcgamer.com/uk/the-making-of-pandemic-legacy)). Lessons: show the four quarters up front; let intensity levers adapt to how tables are doing; make consequences for residents permanent within the session.

**Twilight Struggle.** Playing a card for operations triggers the opponent's event, which "created the paranoia" the designer wanted; scoring cards are hidden in hand so the holder knows when a region will score; the design builds in "incomplete agency", pressure from the opponent and from the game itself; card-based rules put "the rules that matter for the current situation in front of the player"; and uncertainty is shared, since "opponents usually feel the same way" ([The Forge, Ananda Gupta](https://theforge.defence.gov.au/wargaming/wargame-design-decisions-twilight-struggle-and-elsewhere)). Lessons: secret briefs are hidden scoring cards; a mayday from another parish is an opponent-triggered event; print each dilemma's rule on the card.

**Diplomacy online.** Backstabbr adjudicates on a schedule, offers "Resolve orders once all countries have issued orders", lets a gamemaster pause or alter adjudication and invite replacements, and applies civil disorder (no orders means units hold) when a player submits nothing ([Backstabbr FAQ](https://backstabbr.com/faq)). A live virtual tournament in 2020 ran 15-minute order deadlines and 8-minute adjustment phases on 11 boards; the site did not push adjudications so players had to reload; text negotiation was slow and lost tone, so players made roughly 182 phone calls in two games; and players could not see other boards' standings, which removed a source of pressure ([Diplomatic Pouch](https://diplom.org/uk/pouch/Zine/S2020M/Birsan/vdixiecon.html)). Lessons: simultaneous submission with a visible deadline and an early-resolve button; a default action for a table that does not submit; push results, never ask tables to refresh; show cross-table standings; let negotiation be voice, in the room.

## 2. Tech stacks

### 2.1 PixiJS v8 (the chosen renderer)

v8 adds a WebGPU backend beside WebGL, with the warning that WebGPU "does not automatically guarantee improved performance over WebGL in all scenarios"; both renderers got faster because the render loop "only updates what it needs to"; initialization is async so only the needed backend loads. Containers with `isRenderGroup: true` move transform handling to the GPU, which the team calls "a true 2D hardware-accelerated camera" for panning and zooming large static worlds. The Bunnymark figures for 100k sprites, v7 to v8: moving sprites ~50 ms to ~15 ms CPU and ~9 ms to ~2 ms GPU; static sprites ~21 ms to ~0.12 ms CPU. The library is one package (`pixi.js`) with tree shaking; Graphics was redesigned around a Canvas-2D-like API; there are about 21 blend modes as filters with advice not to overuse them ([PixiJS v8 launch](https://pixijs.com/blog/pixi-v8-launches)).

Performance guidance from the official tips: sprites batch up to 16 textures per draw depending on hardware; small Graphics batch when 100 points or fewer; changing blend modes breaks batches; use spritesheets to minimize texture count and `@0.5x` sheets on weak devices; culling is off by default and is enabled per object with `cullable = true` (helps when GPU-bound, hurts when CPU-bound); avoid changing Text every frame and use BitmapText for live numbers; set `hitArea` and `interactiveChildren = false` to keep the event system cheap; `antialias: false` and `useContextAlpha: false` help older devices ([PixiJS performance tips](https://pixijs.com/8.x/guides/concepts/performance-tips)). Culling is now in core: `cullable`, `cullArea` (global coordinates) and `Culler.shared.cull(app.stage, app.screen)` in a ticker callback ([culling API write-up](https://dev.to/fur-gaming/optimizing-rendering-with-pixijs-v8-a-deep-dive-into-the-new-culling-api-e52)).

Tilemaps: `@pixi/tilemap` v5 pairs with PixiJS v8; `CompositeTilemap` manages per-instance limits; a tilemap is capped at 16k tiles by default ([pixi-tilemap](https://github.com/pixijs/pixi-tilemap)). Camera: `pixi-viewport` 6.0.3 offers drag with deceleration, pinch and wheel zoom, follow, snap, clamp and bounce; its listing does not state which PixiJS major it supports, so verify against v8 before adopting ([pixi-viewport](https://www.jsdelivr.com/package/npm/pixi-viewport)). The render-group camera in core may be enough for one island.

### 2.2 Phaser 4

Launched April 2026. It replaced Phaser 3's pipelines with render nodes, each doing one task; `SpriteGPULayer` keeps sprite data in a GPU buffer and draws in one call (about 168 bytes per member, millions of static objects); `TilemapGPULayer` draws a whole layer as one quad so cost scales with screen pixels, not tiles; Phaser Compact Texture atlases are 90-95% smaller than JSON atlases; migration is "mostly mechanical" ([Phaser 3 vs 4](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4)). Batches end at 16,384 quads or on a shader change; keep draw calls to "a few hundred at most"; data uploads are the main bottleneck ([Phaser 4 rendering concepts](https://phaser.io/tutorials/phaser-4-rendering-concepts)). Verdict: a full game framework (scenes, input, physics, tweens) whose extra layers we do not need when the simulation is in Rust; its GPU tilemap idea is worth stealing if the island map ever gets heavy.

### 2.3 Babylon.js and Three.js

Both are 3D-first. Three's `InstancedMesh` renders many objects sharing one geometry and material in one draw call, with manual `needsUpdate` flags and bounding volumes ([three.js docs](https://threejs.org/docs/pages/InstancedMesh.html)). Babylon requires a `SpriteManager` even for one sprite, offers packed sheets and, since 4.1, Sprite Maps for grid-based 2D levels with thousands of sprites ([Babylon.js sprites](https://doc.babylonjs.com/features/featuresDeepDive/sprites)). Verdict: only if the board becomes true 3D terrain. For a readable civic map on a projector, 2D wins.

### 2.4 Bevy on WASM

wgpu targets WebGPU where available and falls back to WebGL2, and "the WebGL2 backend is still missing some features compared to the native and WebGPU backends"; builds use the `wasm32-unknown-unknown` target and `wasm-bindgen --target web`; and, decisive for us, "WebGPU requires a secure context, so serve from 127.0.0.1 or localhost, not 0.0.0.0" ([wgpu web platform notes](https://wgpu.rs/doc/wgpu/documentation/platforms/web/index.html)). Bevy's examples README documents the browser path under Setup, Build & Run, WebGL2 and WebGPU, Audio in browsers, Optimizing and Loading Assets ([Bevy examples README](https://github.com/bevyengine/bevy/blob/main/examples/README.md)); I could not read that section through the fetch tool, so treat it as a pointer. Verdict: Bevy-in-browser puts the whole UI in Rust and ties us to a WebGL2 fallback on a LAN. Our decision to keep Rust for the core and TypeScript/PixiJS for the shell stands. The useful Bevy-adjacent pieces are networking crates (see 3.7).

### 2.5 Performance on projectors and laptops

- A browser RTS already runs on Intel HD Graphics at 1024x768 ([Chrono Divide](https://chronodivide.com/)); a civic map with a few hundred sprites is far below that.
- Chrome stops calling `requestAnimationFrame` for pages in the background (since 2011), limits background timers to once per second, and since Chrome 57 applies a CPU budget after 10 seconds hidden that refills at 0.01 s per second; pages with WebSockets or WebRTC are exempt from the budget but not from the once-per-second rule ([Chrome background tabs](https://developer.chrome.com/blog/background_tabs)). Chrome 88 adds intensive throttling (one wake per minute) for pages hidden over five minutes with no WebRTC and no audio ([Chrome 88 timer throttling](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)). Implication: the projector board must be a visible window on the extended display, never a background tab, and the host process must not live in a browser tab that can be hidden. Use the Page Visibility API to warn when a table's tab is hidden ([MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)).
- Use spritesheets, BitmapText for counters, `antialias: false` on weak machines, and culling only when GPU-bound ([PixiJS tips](https://pixijs.com/8.x/guides/concepts/performance-tips)).

### 2.6 Single-file offline packaging

`vite-plugin-singlefile` inlines all JavaScript and CSS into `dist/index.html` so an app ships as one file that opens without a server; from `file://` it supports localStorage, hash routing and relative local files but not History-API routing or cookies; it supports one entry point; `public/` assets are not inlined ([vite-plugin-singlefile README](https://cdn.jsdelivr.net/npm/vite-plugin-singlefile@2.3.3/README.md)). For the WASM core, `wasm-bindgen --target web` emits an ES module needing no post-processing, and `--target no-modules` emits a classic script you initialize manually ([wasm-bindgen deployment](https://rustwasm.github.io/docs/wasm-bindgen/reference/deployment.html)); embedding the `.wasm` as a base64 string in the HTML and feeding it to `init` is the straightforward single-file route (our `viewer/build.mjs` already does the single-file step for the replay viewer, see [[2026-10-18-overnight-build-log]]). Note that `file:` is a potentially trustworthy scheme under the secure-context rules ([MDN Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_contexts)), which matters for a fully offline, no-network fallback of the board on the facilitator laptop.

## 3. Multiplayer architecture for six tables

### 3.1 Deterministic lockstep: the lineage

**Age of Empires (1997).** Every machine runs the same simulation and receives the same commands, not unit state. Communication turns were typically 200 ms; commands issued in turn N execute in turn N+2. Each client reports the frame rate it can sustain and its longest ping in a two-byte "Turn Done", and the host sets the turn length, raising it quickly under latency and lowering it slowly. Clients checksum the world, objects, pathing and targeting; a mismatch flags "out of sync" and stops the game, and because small differences compound, the root cause could be far in the past. Random numbers were seeded and synchronized, simulation code had to make the same number of random calls on every machine, and non-simulation randomness (terrain sounds) was kept outside. Latency under 250 ms was unnoticeable, 250-500 playable, above 500 noticeable, and consistent latency felt better than variable. Players issued a command every 1.5-2 seconds with spikes of 3-4 per second, and filtering repeated same-location commands removed most spikes ([1500 Archers on a 28.8](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond)).

**Glenn Fiedler.** Lockstep bandwidth "is proportional to the size of the input, not the number of objects"; a machine cannot advance frame n without input n; floating-point determinism across compilers, OS and instruction sets is hard and "there's no silver bullet"; a playout delay buffer (100 ms in his demo) absorbs jitter; over TCP, loss stalls the simulation (visible hitches at 100 ms latency with 1% loss); over UDP with every packet carrying all unacknowledged inputs, the demo worked at 2 seconds of latency and 25% loss ([Deterministic Lockstep](https://gafferongames.com/post/deterministic_lockstep/)).

**Supreme Commander / Demigod (Forrest Smith).** Simulation at a fixed 10 ticks per second with a separate full-frame-rate user layer; the engine hashes the full game state once per second and a mismatch shows "Desync Detected" and ends the game with no recovery; an uninitialized variable is the most common cause; rare desyncs appeared in about 5% of games over an hour; one dangling-pointer desync took almost a week to find ([Synchronous RTS engines and a tale of desyncs](https://www.gamedeveloper.com/design/opinion-synchronous-rts-engines-and-a-tale-of-desyncs)).

**Factorio.** Deterministic lockstep means every client must simulate every tick identically; on a desync the player reconnects and re-downloads the map, and the game writes a desync report containing server and client state for comparison ([FFF-188](https://factorio.com/blog/post/fff-188)). Latency hiding: a "latency state" copies the relevant parts of the real state each tick and replays the player's not-yet-applied local actions on top of it; movement, selection, GUI open/close and building are predicted; fighting is not, because its state changes cascade; when the real state contradicts the prediction, the real state wins ([FFF-83](https://factorio.com/blog/post/fff-83)).

**OpenRA.** Orders generated on net frame X apply on X+dX, typically 2-6 net frames (6-18 ticks at the default 25 ticks per second); in 2021 the project moved order-latency control from clients to the server so latency can later vary during a game ([OpenRA PR #19632](https://github.com/OpenRA/OpenRA/pull/19632/files)).

**0 A.D. and Spring** add the state-classification and coding rules quoted in 1.1.

### 3.2 Host-authoritative state synchronization

Fiedler's alternative sends inputs and state: each packet carries a sequence number, recent inputs and a bounded set of per-object updates chosen by a priority accumulator (his example budget is 256 kbit/s); it needs no determinism because real state corrects drift, and it keeps extrapolating when input is missing instead of stalling; the cost is that it is "an approximate and lossy synchronization strategy" and developers "spend considerable time tracking down extrapolation divergence and pops" ([State Synchronization](https://gafferongames.com/post/state_synchronization/)).

The browser frameworks mostly live here. Colyseus is server-authoritative: room state is declared as a Schema and clients receive only binary delta patches ([Colyseus docs](https://docs.colyseus.io/)). Rune splits a game into `logic.js` (pure `setup` and `actions`, JSON-serializable state) and `client.js`; the server runs the actions in a VM as ground truth, broadcasts valid actions, ignores invalid ones, and sends `stateSync` to players who join, reconnect or restart; clients predict and roll back ([Rune: syncing game state](https://developers.rune.ai/docs/how-it-works/syncing-game-state)). Croquet runs a deterministic model on every client while reflectors, "stateless, public, message-passing services located in the cloud", fan out events, and periodic snapshots let late joiners catch up ([Croquet tutorial](https://croquet.io/sdk/docs/tutorial-2_1_model_view_reflector.html)).

### 3.3 Where the Crucible sits

Six tables submit a handful of commands per quarter: an allocation, aid answers, dilemma choices, perhaps a free-text note. Bandwidth is irrelevant on either model. What matters is authority, recovery and the research instrument: `crucible replay` must reproduce the state hash ([[decision-2026-10-18-restart]]). That argues for lockstep's input-only model with a relay topology and snapshot recovery:

- One ordered command log owned by the host; every client and the host run the same WASM core.
- Commands apply at a tick the host assigns (OpenRA's X+dX), so all cores see the same order; with per-quarter decisions a one-second delay is invisible, well under AoE's 250 ms threshold for noticing in a twitch RTS.
- Every client reports a state hash per tick (AoE, Supreme Commander); a mismatch does not end the session, it triggers a Factorio-style resync of that client from the host's snapshot plus log tail.
- Late join and rejoin replay the log through the core (fast; our core already does this for `replay`), or load a snapshot and the tail.
- The run log is the command log plus the content hash, so the room's game and the research artifact are the same file.

### 3.4 WebSocket versus WebRTC

WebSockets run over TCP, ordered and reliable, always through a server, 99%+ browser support, low-to-medium complexity; WebRTC data channels run over SCTP on UDP, optionally unreliable and unordered, peer-to-peer after signaling, needing STUN/TURN for NAT traversal, 95% support and high complexity ([websocket.org comparison](https://websocket.org/comparisons/webrtc/)). Rune's engineers call WebRTC "considerably more complicated", note that its signaling usually rides a WebSocket anyway, and judge WebTransport not ready ([Rune blog](https://developers.rune.ai/blog/webrtc-vs-websockets-for-multiplayer-games)). The head-of-line blocking that makes TCP wrong for a 60 Hz shooter does not matter for six commands per quarter.

WebRTC also has specific local-network hazards. Browsers now replace local IPs in ICE candidates with mDNS `.local` names by default (Chrome, Edge, Firefox, Safari); resolution happens over multicast and "fails silently where multicast is blocked", does not cross subnets without a proxy, and parsers expecting IPs drop the candidates ([BlogGeek.me](https://bloggeek.me/psa-mdns-and-local-ice-candidates-are-coming/)). A reported failure shows a server unable to resolve a browser's `.local` candidate and tearing down the session ([Janus forum](https://janus.discourse.group/t/ice-fails-on-local-network/271)). Host candidates carry "the true address of the remote peer" ([MDN RTCIceCandidate.type](https://developer.mozilla.org/docs/Web/API/RTCIceCandidate/type)), so same-LAN peers can connect without STUN (inference), but only if the mDNS step works on that router. geckos.io, a WebRTC client-server library, needs TCP 9208 for signaling plus a UDP range (default 1025-65535) and tells developers without UDP forwarding experience that WebSocket "is slower but simpler" ([geckos.io README](https://github.com/jamesward1/geckos.io)).

Verdict: WebSocket to a host on the LAN. No ICE, no multicast dependency, one port.

### 3.5 Local-network play with no internet

- **Venue wifi isolates clients.** Client isolation means a device "should only be able to reach the internet router, not other guests' devices"; without it the author saw 4,208 other devices on a hotel network ([Hotel-Online](https://www.hotel-online.com/news/the-crucial-role-of-client-isolation-in-hotel-wi-fi)). Assume the venue network blocks table-to-host traffic. Bring the network.
- **A travel router works with no uplink.** A GL.iNet owner was told to leave the router disconnected from any internet source, complete first-time setup, and connect devices, which "should all be on the same subnet and be able to see each other" ([GL.iNet forum](https://forum.gl-inet.com/t/using-a-gl-ar300m16-travel-router-as-standalone-wi-fi-without-internet-connection/40720)). Test client count and client isolation settings on the specific router before the session.
- **Plain HTTP on a LAN IP is not a secure context.** Potentially trustworthy origins are `https`, `wss`, `file`, loopback (`127.0.0.0/8`, `::1`), `localhost` and browser-authenticated schemes; `http://example.com` is not secure and private ranges are not on the list ([MDN Secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_contexts)). Service workers are limited to secure origins, "HTTPS sites, basically", plus `http://localhost` ([Chromium service worker FAQ](https://www.chromium.org/blink/serviceworker/service-worker-faq)). WebGPU requires a secure context ([wgpu notes](https://wgpu.rs/doc/wgpu/documentation/platforms/web/index.html)). Consequences on a LAN at `http://192.168.8.1`: no service worker, no PWA install, no WebGPU; WebGL, WebSocket (`ws://`), localStorage and the WASM core all work.
- **HTTPS on a LAN is possible but costly for guests.** mkcert creates a local CA and issues certificates for names and IP addresses, but it is "meant for development purposes, not production", and on iOS and Android the root CA must be installed manually on each device ([mkcert](https://github.com/FiloSottile/mkcert)). Installing a CA on a nurse leader's phone is not acceptable. Chromium's `--unsafely-treat-insecure-origin-as-secure` is a test flag ([Chromium FAQ](https://www.chromium.org/blink/serviceworker/service-worker-faq)). Design for the insecure context instead.
- **"Offline" therefore means: the host serves the single-file app over HTTP on its own router**, the WASM core and all content ride inside that one file, and the facilitator laptop also holds a `file://` copy of the board as the last-resort fallback (a `file:` page is a secure context, though it cannot host the tables).

### 3.6 Reconnects and late joins

Colyseus holds a dropped client's seat with `allowReconnection()` for N seconds or `"manual"`; the SDK retries with exponential backoff while the `room` object lives, and after a page reload the client calls `client.reconnect(token)` with a token saved to `sessionStorage` that changes on every connection; on success the server sends a full snapshot merged into the existing tree; the docs suggest about 30 seconds for fast games and about 5 minutes for turn-based ones, and warn not to delete player data in `onDrop` ([Colyseus reconnection](https://docs.colyseus.io/room/reconnection)). Kahoot lets a disconnected player rejoin "as your previous player" rather than creating a new entry, and late joiners can enter while joining is open, missing completed questions ([Kahoot join](https://support.kahoot.com/hc/articles/360039890713)). Croquet serves snapshots to late joiners ([Croquet](https://croquet.io/sdk/docs/tutorial-2_1_model_view_reflector.html)); 0 A.D. requires the rejoin snapshot to be compact and safe against malicious data ([Pyrogenesis](https://docs.wildfiregames.com/pyrogenesis/serialization.html)); Factorio re-downloads the map ([FFF-188](https://factorio.com/blog/post/fff-188)).

For the Crucible: the seat is the parish, not the device. Any device that enters the room code and picks a parish claims that seat, subject to facilitator approval when the seat is already held; the seat never expires during the session (Colyseus `"manual"` semantics); rejoin replays the command log through the WASM core. A table that submits nothing gets the civil-disorder default (Backstabbr) and the facilitator sees it.

### 3.7 How the deterministic WASM core fits

WebAssembly's permitted nondeterminism is "limited, local": NaN bit patterns and the sign of generated NaNs, threads, some SIMD cases, and resource exhaustion; outside those cases execution is deterministic ([WebAssembly nondeterminism](https://www.webassembly.org/docs/nondeterminism/)). Shipping the same `.wasm` to every table and the host removes the compiler-and-CPU variance that bit AoE, Supreme Commander and 0 A.D. (which answered it with fixed-point `CFixed_15_16` and fixed-size types). Keep the core's existing rules: one ChaCha20 generator, ordered maps, integer ticks, no wall clock ([[decision-2026-10-18-restart]]); never branch on a NaN; keep presentation randomness (animation jitter, ambient sound) out of the core as AoE kept terrain sounds out; initialize everything (Spring). Hash per tick in the core and expose it to the shell for comparison.

The Rust browser ecosystem has rollback P2P if it is ever wanted: GGRS is a GGPO-style rollback library in safe Rust that runs in browsers through matchbox's WebRTC sockets ([GGRS](https://github.com/gschup/ggrs)); `matchbox_socket` targets WASM and native and `matchbox_signaling` is a self-hostable signaling server that "must be reachable by all clients over HTTP or HTTPS" ([matchbox_signaling](https://docs.rs/matchbox_signaling)). Not needed for six tables and a host, and it inherits the WebRTC-on-LAN hazards above.

## 4. Facilitated and serious-game precedent

**Fishbanks (MIT Sloan).** Teams act as fishers, buy, sell and build ships, choose where to fish, negotiate, and instructors can introduce auctions, permits and quotas ([MIT Sloan](https://mitsloan.mit.edu/teaching-resources-library/fishbanks-a-renewable-resource-management-simulation)). Instructors report that teams of two or three worked best, each team names a captain who enters the team's decisions on the website each round, teams should use laptops rather than phones or tablets, one 90-minute class for play with the debrief in the next class, and two optional prizes: largest financial assets, and the team that most promoted sustainability by participant vote. One team's cheating on a self-imposed harvest pause became the debrief's lesson on sanctions ([Fishbanks instructors' notes](https://sustainabilityscience.org/course/course-library/learning-games/fishbanks-instructors.pdf)). Closest analogue to our allocation round and our two counters.

**MIT Beer Game online.** A multiplayer web simulation for groups from about four to 400, remote, in person or hybrid, no preparation, with instructor materials for running and debriefing; its stated lesson is how unintended consequences erode trust between roles ([MIT Sloan](https://mitsloan.mit.edu/teaching-resources-library/mit-sloan-beer-game-online)).

**World Climate (C-ROADS).** Delegations negotiate, get immediate model feedback, see that round-one pledges fall short, and negotiate again; more than 28,000 people in over 60 nations have played, including policymakers and executives ([MIT Better World](https://betterworld.mit.edu/role-playing-action-climate-change/)). The two-round "see the consequence, try again" structure is Pandemic Legacy's make-up test in a workshop.

**Harvard Business Publishing: Everest.** Teams of five, each member in one of five roles with its own objectives, information and limited resources, six simulated days, three hidden challenges, 3-4 hours total (about 30 minutes intro, 1-1.5 hours play, 45-60 minutes debrief) ([Forio Everest](https://forio.com/store/harvard-everest-leadership-teamwork-simulation/)). Facilitator configuration: auto-assign teams of five or drag learners manually; Mirror Roles up to ten per team and Observer Roles for uneven classes; the facilitator chooses whether the Leader role or the facilitator advances each day; access levels gate what learners see before play; team chat, videos and survey can be toggled; learners must already be enrolled ([HBP help](https://help.hbsp.harvard.edu/hc/en-us/articles/40763356827795-How-do-I-Configure-Leadership-and-Team-Simulation-Everest-V3)). The underlying platform, Forio Epicenter, supports multiplayer worlds with teams, facilitator roles and shared state, facilitator dashboards, and cloud or on-prem deployment ([Forio Epicenter](https://forio.com/products/epicenter/)).

**Kahoot.** Players go to kahoot.it, enter the host's PIN, type a nickname or take a generated one, usually with no account; the host screen shows the PIN and a QR code; optional 2-Step Join makes players match a four-tile pattern that changes every seven seconds; disconnected players can rejoin as their previous player; late joiners can enter while joining is open ([Kahoot join](https://support.kahoot.com/hc/articles/360039890713), [hosting tips](https://support.kahoot.com/hc/articles/360039900153)). Hosts are told to use the "campfire moment" after each answer to discuss, to show the top five and comment on changes, and to let podium finishers show their screens ([hosting tips](https://support.kahoot.com/hc/articles/360039900153)).

**Jackbox.** Join at jackbox.tv with a four-letter room code and a name on any device with a browser supporting cookies, WebSockets, HTML5 and JavaScript; the device running the game cannot also be a controller ([Jackbox support](https://support.jackboxgames.com/hc/en-us/articles/15794759479959-How-do-I-join-a-game)). Design principles: phones as controllers so nothing is installed; shared screen for public information and phones for private information, which enables hidden roles; inputs limited to a button, a drawing or a line of text; "the games never ask players to make multiple choices in a given moment"; the interface should be "dumb enough for me to understand"; TV-style pacing that "pulls you along" ([Built In](https://builtin.com/media-gaming/jackbox-games-design-party-pack)). Accessibility additions include reading the room code aloud, subtitles and a reduced-motion toggle ([Jackbox blog](https://www.jackboxgames.com/new-accessibility-features-in-the-jackbox-party-pack-7/)).

**Conducttr (crisis exercises).** Vocabulary: an inject is "a single piece of exercise content or event"; the MSEL is the "primary timeline that drives all injects"; the facilitator is "the controller of the exercise"; decision points are where player choices branch the scenario; observers watch silently ([Conducttr dictionary](https://helpdocs.conducttr.com/start-here/getting-started/dictionary-of-conducttr-and-crisis-exercise-terms)). The Facilitator Dashboard lets the controller publish or pause injects, enter the exercise as any player, impersonate personas, add or remove participants and rearrange teams during the exercise, start and stop pattern-of-life content, replay injects from a grid of buttons, assess players against schemas, run two- or three-screen layouts, and lock the dashboard while the exercise keeps running ([Facilitator Dashboard](https://helpdocs.conducttr.com/feature-documentation/running/exercise-control/facilitation/facilitator-dashboard)). This is the DM console we described in [[decision-2026-10-19-nursing-leaders-60min]], in a commercial product.

**Diplomacy gamemasters.** Backstabbr GMs can pause or alter adjudication, read all press and invite replacements, and cannot submit orders ([Backstabbr FAQ](https://backstabbr.com/faq)).

**What they do about join codes, device mix and facilitator control, in sum.** Join codes: short (four letters or a PIN) on a shared screen, no accounts, with a rejoin-as-yourself path (Kahoot, Jackbox); the enrolled-user model (HBP) is the opposite end and does not fit a 90-minute room. Device mix: public state on the shared screen, private state on personal devices (Jackbox); one laptop per team with a captain entering decisions (Fishbanks); and the host device is never a controller (Jackbox). Facilitator control: advance the day or let the team's leader do it (Everest), pause or publish injects and move people between teams live (Conducttr), pause adjudication and substitute players (Backstabbr), and a debrief with a vote-based prize beside the numeric one (Fishbanks).

## 5. Recommendations for The Values Crucible

### 5.1 Stack

1. **Core:** the existing deterministic Rust crate compiled to WASM with `wasm-bindgen --target web`, content embedded, per-tick state hash exposed. One `.wasm` for the CLI's replay checks, the tables, the projector board and the host.
2. **Shell:** TypeScript with PixiJS v8 in WebGL mode (WebGPU cannot run on `http://` LAN origins). One `isRenderGroup` container for the island as the camera; `@pixi/tilemap` v5 only if the base map needs tiles (a single large island texture plus sprites may do); BitmapText for live counters; spritesheets; culling off until measured.
3. **Host:** a small Node process on the facilitator laptop that serves the single-file app over HTTP, owns the WebSocket room and the ordered command log, runs the same WASM core as the authority, and writes the run log. Colyseus is a reasonable base if we want its room, Schema and reconnection machinery; a bare `ws` server with our own log is also small enough to own outright.
4. **Packaging:** one HTML file built with `vite-plugin-singlefile` (or our existing `build.mjs` approach) with the `.wasm` inlined; the same file serves tables, the projector and the `file://` fallback.
5. **Not recommended now:** Bevy in the browser (whole UI in Rust, WebGL2-only on LAN), Phaser (framework layers we do not need), WebRTC of any flavour (mDNS and ICE hazards on a venue LAN), Croquet/Multisynq and Rune (cloud authority).

### 5.2 Network topology

```
 travel router (own SSID, no uplink)
   |
   +-- facilitator laptop: Node host at http://192.168.8.2
   |     - serves crucible.html (single file, WASM inside)
   |     - WebSocket room, room code on the projector
   |     - ordered command log, assigns apply-tick, hashes per tick
   |     - writes the run log (same schema as `crucible run`)
   |     - projector window: the shared board (visible window, never a hidden tab)
   |
   +-- six table laptops (or tablets): open the URL or scan the QR, type the code,
   |     pick a parish; run the WASM core locally for instant local feedback;
   |     send commands; report hash; resync from snapshot on mismatch
   |
   +-- DM/facilitator console (second laptop or second window): inject, pause,
         reassign seats, see who has not answered, release the quarter
```

Rules: commands only, never state, over the wire; the host assigns the tick; hash every tick, resync on mismatch, never stop the session; seats are parishes and never expire; a table that does not submit by the deadline gets the default action and the facilitator sees a flag; the run log is the command log.

### 5.3 Ten UX patterns to copy

1. **Strategic view with an icon layer** on the projector; tables zoom locally (Supreme Commander, Sins).
2. **A forecast bar** for Hurricane Midas that drives the quarter's tempo and signals relief as well as danger (Frostpunk).
3. **Two counters, always visible:** doses shipped and people safe, with the island map explaining itself in one screenshot (Mini Metro, Territorial).
4. **Named residents, three or four per table,** with permanent consequences reported on the board, not 500 anonymous citizens (Frostpunk, Pandemic Legacy).
5. **Secret briefs as hidden scoring cards** and maydays as opponent-triggered events; each dilemma card carries its own rule (Twilight Struggle).
6. **Simultaneous submission with a visible deadline and "resolve when all six are in",** results pushed to every screen, a default when a table is silent (Backstabbr, DixieCon).
7. **One choice at a time on the table's screen,** public state on the shared screen, private state on the table's device (Jackbox).
8. **Join by a code on the projector, no accounts, rejoin as your parish,** late seats allowed with the facilitator's nod (Kahoot, Jackbox).
9. **Facilitator controls from crisis exercises:** publish or pause injects, move people between tables, advance the quarter, observe who has not acted (Conducttr, Everest).
10. **Two prizes and a campfire moment:** a numeric standing and a vote-based award, with the facilitator narrating leaderboard changes between quarters (Fishbanks, Kahoot). Judge the values gap in the debrief, not during play (Frostpunk's ending slides).

### 5.4 Pitfalls to avoid

- **Trusting venue wifi.** Client isolation blocks table-to-host traffic. Own the router and rehearse with it.
- **Assuming a LAN origin is "secure".** `http://192.168.x.x` has no service workers, no PWA, no WebGPU. Do not build the offline story on them; build it on a single file served by the host.
- **WebRTC on a LAN.** mDNS `.local` candidates fail silently where multicast is blocked; signaling needs a server anyway. Use WebSockets.
- **Running the host or the board in a tab that can be hidden.** Chrome stops rAF and throttles timers in background tabs; keep the projector board a visible window and the host a Node process.
- **Letting presentation touch the simulation.** Every desync story (uninitialized variable, dangling pointer, unsynced random call) comes from crossing that wall. Keep randomness and animation out of the core; hash in the core.
- **Ending the session on a desync.** RTS games stop the game; a facilitated room cannot. Resync the one client.
- **Using the device as the identity.** Phones die and laptops reboot; the parish seat must outlive them.
- **Dilemmas whose ethical choice is also the efficient one.** They measure nothing (Frostpunk's critics).
- **Too many unit and resource types.** StarCraft II cut to 14 per race; six parishes with a handful of distinct, visually different resources is plenty.
- **Underestimating the UI.** Two Point Studios called it the most collaborative and underestimated task; Age of Empires III's UI grew until criticism arrived. Budget it and test it with people who are not gamers.
- **A soft launch in front of executives.** "You only get word-of-mouth once."
